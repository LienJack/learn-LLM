# GPT Pro コース総合レビュー用プロンプト

`all-articles-for-gpt-review.md` の全文を GPT Pro に貼り付けたあと、次のプロンプトを使います。

```markdown
あなたは、経験豊富な中国語技術教材編集者、LLM エンジニアリングコース設計者、機械学習教育レビュー担当者です。以下の『LLM をゼロからドメイン小型モデルへ』19本のコース記事集をレビューし、体系的なレビュー意見と修正提案を出してください。

## コースの位置づけ

これは API チュートリアルではなく、概念だけを説明する一般向け解説でもありません。Python は書けるが、深層学習 / LLM エンジニアリングを体系的に学んだとは限らない学習者向けの中国語教材です。

コースの目標は、学習者が最小の学習ループから出発し、段階的に次の流れを理解することです。

学習ループ -> next-token 言語モデリング -> Tokenizer / Dataset -> Embedding -> Attention -> Transformer -> Mini GPT -> Hugging Face ワークフロー -> SFT -> LoRA / QLoRA -> ドメインデータエンジニアリング -> RAG -> 蒸留 -> 評価 -> 安全性とモデルカード -> 量子化デプロイ -> 法律 / 医療ドメイン小型モデルプロジェクト -> 汎用ドメインモデル工程テンプレート

このコースの中心線は次の問いです。

> 文脈に基づいて信頼できる回答を生成させるには、どの能力をどの順番で補う必要があるのか。その能力は、実験、テスト、失敗例によってどう検証されるのか。

## 対象読者

- Python は書け、基本的な PyTorch コードは読める。
- 深層学習、確率モデリング、情報理論、GPU 学習、分散システムを体系的に学んでいるとは仮定しない。
- 「demo を動かせる」からさらに進み、「学習でき、評価でき、デプロイでき、ガバナンスできる」LLM エンジニアリングを学びたい。

## 文体要件

百科事典的な項目や論文風ではなく、「問題駆動の技術概念ブログ / 教材」としてレビューしてください。

各章では、次を優先するべきです。

1. その概念がなぜ出てきたのかを先に説明し、そのあとで何であるかを説明する。
2. 学習者が実際に抱く困惑や能力ギャップから始める。
3. 明確な問題の進化チェーンで進める：
   もともとは何だったか -> どんな問題が出たか -> どんな仕組みを導入するか -> 何を解決するか -> どんな新しい問題が残るか -> 次章へどうつながるか。
4. 通し例をできるだけ再利用する。特に「契約条項リスク識別 / 法律契約レビュー」を中心にし、医療QAを2つ目の高リスク領域例として使う。
5. 用語が出たら、まず普通の言葉で言い換え、そのあと技術的な境界を示す。
6. 並列した定義リストにしない。用語を積み上げない。
7. 各章に工程感を残す：shape、入力出力、loss、最小実装、実験観察、失敗モード、テスト受け入れ条件。
8. 技術的に誠実に書く：適用境界、非目標、よくある誤解、高リスク場面を説明する。

## 重点的にレビューしてほしい点

### A. 全体構造

- 19章の進化チェーンは自然か。
- 第1章から第19章まで、テーマの並列ではなく明確な進行があるか。
- 章間の接続が弱く、「前章で残った問題 / 本章で解く問題」を補う必要がある箇所はどこか。
- 章の順序、タイトル、責務で調整すべきものはあるか。
- 重複、断絶、飛躍、説明前に概念が出る問題はないか。

### B. 各章の品質

各章について確認してください。

- 冒頭は実際の問題から始まっているか。
- 「この章で本当に解決したい問題」は十分鋭いか。
- 「問題の連鎖」は本文全体を支えているか。
- Concept Card は役に立っているか、それとも形式的な表になっているだけか。
- 通し例は一貫し、具体的で、実行可能か。
- 抽象的すぎる、教材口調すぎる、定義の積み上げに見える段落はないか。
- 類比、反例、境界説明、最小例を補うべき場所はどこか。
- 終わり方は自然に次章へつながっているか。

### C. 初学者の読みやすさ

- 対象読者にとって速すぎる、飛躍している、用語密度が高すぎる段落はどこか。
- 数学的対象、shape、loss、学習詳細について、よりゆるやかな導入が必要な箇所はどこか。
- 「工程用語」をより直感的な言葉に翻訳すべき箇所はどこか。
- 図、フローチャート、表、最小コード片を追加すると理解が大きく改善する箇所はどこか。

### D. エンジニアリングループ

各章が本当に次に答えているか確認してください。

- 現在の能力ギャップは何か。
- 重要な数学的対象は何か。
- 入力、出力、パラメータ、loss の shape は何か。
- 最小実装は何か。
- 実験でどう観察するか。
- よくある失敗モードは何か。
- tests は実装が壊れていないことをどう証明するか。

不足している要素がある章では、どこに何を補うべきか明確に指摘してください。

### E. ドメイン小型モデルの主線

「汎用 LLM 基礎から法律 / 医療ドメイン小型モデル工程へ進む」主線が十分強いか、特に確認してください。

- 契約リスク識別の通し例は第1章から継続して機能しているか。
- 法律プロジェクトと医療プロジェクトは単なる追加ケースではなく、前半の能力を総合的に検証するものになっているか。
- RAG、SFT、LoRA、蒸留、評価、安全性、デプロイの境界は明確か。
- RAG、微調整、蒸留を一つに混同するリスクはないか。
- 高リスク領域での拒否、人間レビュー、根拠引用、モデルカード、rollback は十分厳密に扱われているか。

## 出力形式

19本の記事を直接すべて書き直さないでください。まず「レビュー報告 + 修正提案」を出してください。

次の構造で出力してください。

## 1. 全体判断

5-10文で、この文章群の最大の長所、最大のリスク、最優先で修正すべき方向を評価してください。

## 2. 全体構造の修正提案

章をまたぐ提案を5-10件挙げてください。各項目には次を含めます。

- 問題
- なぜ学習体験に影響するか
- どう直すべきか
- 影響する章

## 3. 章別レビュー意見

第1-19章について章ごとに意見を出してください。各章には次を含めます。

- 本章の役割が明確か
- 問題の連鎖が成り立っているか
- 最も強化すべき 1-3 点
- 追加 / 削除 / 移動すべき内容
- 例、図、実験、テスト、失敗モードを補う必要があるか

## 4. 優先度付き修正リスト

P0 / P1 / P2 で分類してください。

- P0：直さないとコース全体の主線または技術正確性に影響する
- P1：学習体験と記事品質を明確に改善する
- P2：表現、タイトル、局所例の最適化などの polish

## 5. 文体統一の提案

19本の記事を後から統一するための、再利用可能な単章執筆テンプレートを出してください。テンプレートは「問題駆動、概念進化チェーン、通し例、工程ループ」に合うものにしてください。

## 6. 書き換え例

代表的だと思う段落を2-3個選び、「教材式 / 定義式の表現」から「問題駆動で、初学者にやさしく、工程境界が明確な表現」へどう直すかを示してください。

## 7. 著者の次アクション

実行可能な修正順序を示してください。どの章から直すか、どう直すか、各修正ラウンドをどう受け入れるかを含めてください。

## レビュー原則

- 技術正確性を文章の美しさより優先する。
- 学習経路の明確さを、より多くの概念を網羅することより優先する。
- 現在の記事の断絶や誤解を解決しない限り、外部知識を過剰に追加する提案はしない。
- 記事をマーケティング文、SNS向けの煽り文、論文レビューに変えない。
- 中国語表現は自然で、明確で、用語密度を低く保つ。ただし工程上の正確性は犠牲にしない。
- すでに十分よい内容がある場合は明確にそう述べる。提案するためだけに無理に欠点を探さない。
```
